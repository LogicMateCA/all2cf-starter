# Outcome

Factory and generated-project Setup can preserve one StyleKit global lock while recording optional ThreeUI Community or React Bits components and HTML Anything recipes. Generated projects also carry the `all2cf-project` Codex plugin so a new AI can use bounded context, authorized updates, official Cloudflare release routing, Expo execution-target routing, compatible upgrades, design governance and read-only health checks without inheriting Factory or canonical Engine administration.

# Scope

- Add a versioned Design Provider Catalog and schema with curated, license-aware, performance-classified entries.
- Persist optional selections in `blueprint.designExtensions`, validate them during Setup, materialization and knowledge generation, and expose them in `/factory` and local `/setup` without loading third-party runtimes.
- Package the generated-project Codex plugin as a source artifact with narrowly routed Skills and no fictional MCP endpoint.
- Keep StyleKit as the global semantic-token owner, shadcn/ui as the ordinary Web product foundation, and third-party components explicit and on demand.

# Verification

- `npm run design:providers:contract`
- Plugin Creator manifest validation and Skill quick validation.
- Web typecheck/build and local `/factory` browser/API persistence check.
- Factory contract proves the generated project carries the Catalog, Blueprint selection and plugin while excluding the Pack library and source-release workflow.
- Knowledge, Agent Map, materialization and change contracts pass.
- Full `npm run verify` passes, including all workspace typechecks, three site builds, bundle budgets and Development/Production Worker dry-runs.
- Local Factory browser acceptance passes four desktop/mobile and light/dark cases with eight screenshots, zero console/page/response failures, and artifact `7101853d52e6918b9d3b1b856350f151536fa5397a3180bcaa6fcc7eb4b00e2f`.
- The local Setup API persisted one React Bits, ThreeUI and HTML Anything selection across reload and then restored the original empty selection.

# Release

Implemented locally. No Worker deployment, database change, Engine Channel publication or Production operation is part of this change.

# Later ownership change

`visual-product-decoupling` supersedes the optional Provider Catalog and `design-governance` ownership introduced here. The independent Visual repository now owns universal visual Providers and the Visual Skill. Starter retains only its functional fallback, a versioned integration receipt and plugin declaration; historical verification in this Change Spec remains evidence for the removed prototype, not current product architecture.
