# Outcome

A copied project can select Expo Push and receive the SDK-compatible native module/config plugin, user-owned device-token registry, server delivery adapter, Setup ticket test and Admin self-device test without carrying any native push dependency when unselected.

# Scope

- Add separate Development/Production EAS project IDs and optional access-token security.
- Add Expo SDK 57-compatible `expo-notifications~57.0.12` only while selected and generate its native config plugin through a receipt-owned mobile plugin registry.
- Add native permission/channel/token registration helpers using the configured EAS project ID; Web remains unsupported by design.
- Add owner-scoped register/list/delete APIs, delivery/ticket evidence, automatic `DeviceNotRegistered` disablement and an Admin-only self-device test.
- Add Setup official links, write-only access tokens and a fixed-message real Expo Push ticket action.

# Verification

- Selected-pack disposable Workerd evidence proves anonymous denial, wrong-project rejection, authenticated device registration/listing and owner-scoped deletion.
- Selected Expo dependency checks, TypeScript, Expo Doctor 21/21, Web/iOS/Android exports and all mobile bundle budgets pass.
- Both Worker configs type/dry-run with isolated project IDs; deselection removes Worker/Mobile/SQL files, dependency, native plugin, variables and receipt ownership, then default regressions pass.
- The local Setup browser matrix passed four responsive light/dark cases, eight screenshots and zero failures after the Push controls were added.
- Physical-device token acquisition, Expo ticket acceptance, delivery receipt, APNs/FCM credentials and installed iOS/Android behavior remain unverified. The Pack therefore stays `implemented`, not `local-verified` or selectable-by-default.

# Release

No remote mobile or Worker release. The current Blueprint leaves Expo Push unselected. A native dependency/config-plugin selection requires a new Development build rather than an EAS Update.
