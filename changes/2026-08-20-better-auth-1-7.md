# Outcome

Starter uses the stable Better Auth 1.7 line across Web, Worker, Expo, schema tooling, and future official plugins from a clean empty-database baseline.

# Scope

- Align `better-auth`, `@better-auth/expo`, and the schema CLI on stable 1.7.1.
- Put the required physical `app_account.issuer` field and issuer-scoped identity uniqueness directly in the empty-project baseline schema.
- Keep legacy identity backfill out of Starter; existing products must own provider mapping and collision review in their own upgrade Change Spec.
- Revalidate Web auth types, Expo cookie resolution and three-platform exports, Worker builds, email delivery contracts, and authentication smoke behavior in an isolated PostgreSQL database.

# Verification

- The 1.7.1 CLI proposal was generated and reviewed. Because Starter databases are an empty-project baseline, its required `issuer` field and compound unique index are incorporated directly into migrations `0001` and `0002`; no legacy backfill migration is retained.
- A clean local workerd smoke against disposable PostgreSQL 18 passed as the schema acceptance test: registration created `local:credential` identity keyed to the stable user ID, then mandatory provider-backed email verification, login, session/preferences, reset and revocation, replacement login, sign-out, and CFsend contract delivery passed.
- Email provider contracts passed for CFsend, Resend, and Cloudflare Email Service. Expo Doctor passed 21/21; Mobile Web, iOS, and Android exports plus budgets passed after revalidating the Better Auth 1.7 Expo storage/cookie path.
- Read-only `npm run db:empty:check` found Production empty. Development contains 1 user, 1 account, 1 email-outbox row, and 20 rate-limit rows from testing; no rows were deleted. Development must be explicitly cleared and both schemas recreated before release.
- Full `npm run verify` passed: AI/knowledge/change checks, both Worker type generations/checks, all TypeScript projects, Vite production build, Web bundle budgets, and both Cloudflare dry-runs. Shared Development/Production schema recreation, live Google return flow, Admin plugin regression, and future Stripe behavior remain release gates rather than local claims.
