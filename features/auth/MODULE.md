# Auth module

Purpose: provide the implemented Web identity foundation, platform administration authority, and shared contracts required for later Expo identity. Organization membership, invitations, and billing remain selectable Better Auth extensions rather than implied core behavior.

- Implemented identity providers: email/password plus independently selectable Google, GitHub and Apple OAuth. GitHub requires verified email access. Apple dynamically signs a six-month ES256 client secret from Services ID, Team ID, Key ID and P8 material, trusts `appleid.apple.com`, and records the native bundle identifier for iOS audience validation.
- Session/token boundary: Host-only Web cookies and Expo SecureStore integration.
- Session authority: PostgreSQL remains authoritative on every request. Cookie session caching is disabled so password reset, sign out, and administrative revocation take effect immediately.
- Login state machine: one email continuation entry in every environment, with no separate registration UI. Existing credential accounts enter their password; unknown emails choose a password and must verify the address before access; accounts created previously through Google or another linked provider receive a six-digit ownership code before they can set their first password. Forgotten-password recovery uses the same bounded OTP proof with a separate purpose. OTP values are hashed, expire after ten minutes, and allow at most five attempts.
- Email verification is mandatory in every environment. The default provider is CFsend; Resend and Cloudflare Email Service are explicit switches. No environment may silently replace delivery with logging or outbox-only behavior.
- Email reliability: each message owns one outbox row, provider identity, stable idempotency key, provider message ID, attempt count, and failure code. CFsend/Resend retry only network, 429, and 5xx failures with the same idempotency key; permanent 4xx responses fail closed.
- Database boundary: Better Auth's built-in PostgreSQL/Kysely adapter uses per-request Hyperdrive pools. Schema changes are reviewed SQL migrations; Drizzle is not installed.
- Account identity boundary: Better Auth 1.7.2 identifies external accounts by `(issuer, account_id)`. The Starter's initial empty-database schema creates that field and unique index directly. Legacy identity backfill belongs to an existing product upgrade and is intentionally absent here.
- Roles and permissions: Better Auth's official Admin plugin owns platform `user` and `admin` roles, bans, session revocation, impersonation support, and user administration endpoints. The Starter does not maintain a parallel `platformRole` field. The optional Organization pack owns tenant `owner`, `admin`, and `member` roles separately and never grants platform Admin access implicitly.
- Upgrade boundary: Better Auth core, Admin, Expo, and every later selected official plugin, including the optional API Key pack, move as one reviewed stable-compatible line. Each upgrade generates a schema proposal, records compatibility, and updates the empty-project SQL baseline when needed.
- Localized authentication errors are a required foundation through `saas.auth-i18n` (English, French and Chinese only). Every other Advanced Identity & Access capability is default-off and receipt-owned; deselection removes its code, dependency, route, SQL and Cloudflare requirements.
- Optional account security: `saas.account-security-2fa` uses Better Auth's aligned built-in Two-Factor server/client plugins for verified TOTP enrollment, challenge cookies, recovery codes, trusted devices and lockout. `saas.auth-passkey` separately owns WebAuthn registration, sign-in, listing and deletion through `@better-auth/passkey`.
- Passwordless entry: Magic Link uses the configured authentication email Provider and a ten-minute one-time link; it does not replace the mandatory verified-email and bounded recovery flow.
- API identity: JWT produces short-lived JWKS-verifiable service tokens with key rotation. Bearer Session authentication remains separate and is not presented as OAuth. OAuth Provider and Device Authorization require JWT; MCP owns its own OAuth Provider instance and therefore conflicts with the standalone Provider. Agent Auth remains experimental, delegated-only, short-lived and PostgreSQL replay-backed.
- Enterprise identity: Generic OAuth validates HTTPS discovery and PKCE; SSO supports operator-configured OIDC/SAML without claiming commercial self-service; SCIM isolates connections, bearer credentials and scopes and requires PostgreSQL interactive transactions.
- Optional login modes: Phone requires the selected Twilio Pack and E.164 OTP delivery; Anonymous creates explicit guest sessions; Google One Tap reuses Google OAuth and loads only on its lazy route.
- Sensitive data handling: provider credentials enter through the local development profile and Worker secrets.
- Local Setup may replace Google, GitHub, Apple or authentication-email Development credentials in project-local `.dev.vars` without reading existing values back. Configure later preserves the selected Provider but leaves a truthful release blocker. `/admin` cannot mutate credentials; it displays runtime readiness, official application links, and sends operators back to local Setup.
- Release rewrites authentication-email requirements as an exclusive provider set: CFsend, Resend, or Cloudflare Email Service. Switching providers removes stale secret names; Cloudflare Email Service uses the `EMAIL` binding and does not require CFsend/Resend credentials.
- Setup verification opens the real Development Better Auth social flow for selected OAuth providers. CFsend and Resend verification sends a user-requested test message through the production email adapter and reports the Provider message ID/attempts without persisting or returning secrets; local Setup cannot fake the Cloudflare `EMAIL` binding.
- Optional Cloudflare Turnstile uses Better Auth's official Captcha plugin for exact credential sign-up, password sign-in and password-reset endpoints. The selected public site key is exposed to the client widget; the secret stays write-only and server-side. Missing tokens, failed Siteverify calls and rejected tokens fail closed. Development and Production widgets must be different.
- Global account entry: every authenticated primary surface exposes the active avatar or initials at the upper right. The menu contains identity, account/settings, System-Light-Dark appearance, language, conditional Admin, help/support, and sign out.
- Global notification entry: the shared signed-in Product Shell places the user-isolated notification Bell immediately before the account entry and links to the full inbox. Notification producers remain owned by their source module.
- Security notification ownership: successful Better Auth Admin role, ban, unban, session-revocation and impersonation mutations append the exact platform audit event and a recipient-scoped in-app security notification. Failed authorization and read-only Admin operations produce neither.
- Shell boundary: the account control participates in the permanent Product Shell registered in `features/product-shell/MODULE.md`. Auth owns identity and permissions; it does not own page navigation, workspace routing or product search.
- Preference ownership: signed-in theme and locale persist on the user profile through `/api/preferences`; signed-out preferences remain device-local defaults. Expo preference UI is still pending.
- Accessibility: the account trigger has an explicit accessible name, menu focus is trapped/restored correctly, and every action is reachable by keyboard or native assistive technology.

All auth changes require explicit threat, migration, and rollback notes in a Change Spec. Keep states and permission behavior documented here.

`npm run auth:flow:contract` prevents registration UI, production lookup fallback, unverified social-account password creation, unhashed OTP storage, and unbounded OTP attempts. `npm run auth:social:contract` covers Google/GitHub/Apple selection, deferred readiness, invalid-provider rejection, explicit no-social selection, the legacy missing-setting Google default, Apple ES256 client-secret claims, and Operations Health alignment with exactly the selected providers.

Local verification uses `npm run auth:email:contract` for CFsend, Resend, and optional Cloudflare Email Service provider behavior. By default, `npm run auth:smoke:dev` creates a temporary empty PostgreSQL database, applies the selected complete Starter baseline, runs real workerd with an explicitly declared CFsend contract double regardless of the product's selected email Provider, verifies the generated service slug, issuer-scoped identity, mandatory email verification, the credential/reset/session cycle, Better Auth Admin and support boundaries, truthful selected/unselected social-provider health, and any selected Organization/Stripe/API Key contracts, then force-drops that database. The smoke child process removes real CFsend, Stripe, and Webhook values inherited from the release shell before loading its disposable env-file, so live credentials cannot escape into or override the contract test. Organization verification covers creation/update/delete, tenant branding metadata, creator/admin/member/custom roles, team limits and membership, invitation accept/reject, non-member denial, member read-only organization API keys, owner key creation, hash-at-rest and owner-delete cleanup. Stripe verification covers empty projection access, foreign-reference denial, invalid-signature denial, valid signed unknown-event acceptance, and replay evidence. API Key verification covers create, hash-at-rest, owner-scoped listing, read-scope acceptance, write-scope denial, no session conversion, and revoke invalidation. An explicit isolated database URL may replace the temporary database. The smoke test never uses a shared Starter database implicitly. Real OAuth callback completion, real CFsend delivery, real Stripe Test Checkout/subscription lifecycle, installed-device SecureStore behavior, and remote environment release remain unverified until exercised in their target environments.

The authenticated browser extension of that same disposable flow passes Product Shell, notification, account menu, mobile navigation, Settings, Support and Admin interactions across desktop/mobile and light/dark modes. Remote Development smoke requires the exact selected social-method list and checks the secure host-only state cookie for each selected Google/GitHub/Apple authorization entry; explicit no-social requires an empty list. This initiation evidence does not prove provider callback completion, real mailbox delivery or native SecureStore.

`npm run auth:schema:generate` creates and drops a temporary empty PostgreSQL database and writes a versioned proposal under ignored `db/generated/`. Upgrades compare that proposal to `db/migrations/`. Starter databases are created empty from the current baseline; no legacy data migration or backfill belongs in this repository. An already initialized product must own its separate upgrade migration.
